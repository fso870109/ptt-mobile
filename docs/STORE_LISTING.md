## Android 前景服務類型

`PttService` 宣告：

`android:foregroundServiceType="microphone|mediaPlayback|location"`

| 類型 | 為什麼需要 | Play Console 聲明時可寫的用途 |
|---|---|---|
| `microphone` | 使用者按住對講時，即使畫面不在最上層也要繼續擷取麥克風並即時送出語音。 | 即時對講（Push-to-talk）。僅在使用者主動按住或系統 PTT 鍵講話時使用麥克風；語音只即時傳送，不錄音、不存檔。 |
| `mediaPlayback` | 其他成員講話時，要在前景服務中播放即時語音，避免系統在背景中斷音訊焦點。 | 播放頻道或一對一的即時對講語音。沒有點播音樂或下載媒體。 |
| `location` | 僅當使用者開啟「分享我的位置」時，前景服務才需要順便帶上位置類型，以便在對講期間持續回報最新位置。 | 工作溝通用的即時位置分享。只保留最新一筆，不建立軌跡。使用者可隨時關閉。 |

**不要**申請與功能無關的前景服務類型（例如 `camera`、`dataSync`、`phoneCall`）。

## 背景位置

目前 AndroidManifest **沒有**宣告 `ACCESS_BACKGROUND_LOCATION`，也沒有「一律在背景追蹤」的行為：

- 只在使用者開啟分享時，使用 `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`（使用中）。
- 前景服務的 `location` 類型是為了在對講進行中（前景服務已在跑）一併回報位置，不是悄悄在背景畫軌跡。
- 系統只保存每個人的最新座標，不保存歷史路徑。
- Play Console 的「位置」應選擇「使用時（foreground）」為主。若審核人員因 FGS `location` 追問背景位置，請說明：未宣告背景位置權限、使用者可關閉分享、無軌跡、用途為團隊協作而非廣告。

若未來要做「App 完全退出後仍持續回報位置」，才需要額外申請背景位置並準備示範影片；目前版本不建議開這一項。

## 權限與用途說明（請求前會先用對話框說明）

| 權限 | 何時請求 | 給使用者看的用途 |
|---|---|---|
| 麥克風 | 進入對講畫面時（若尚未授權） | 按住講話時把聲音即時傳給頻道或私訊對象。不存錄音。 |
| 通知 | 進入對講畫面時（Android 13+） | 顯示前景服務通知，讓對講在背景繼續收聽／發話。 |
| 附近的裝置 / 藍牙連線 | 與麥克風一併說明 | 讓使用者透過已配對的藍牙耳機或 PTT 按鍵對講。 |
| 位置（精確／粗略） | **只有使用者開啟「分享我的位置」時** | 把目前位置與電量分享給同頻道成員及公司管理員／調度員。只保留最新一筆。 |
| 照片／媒體（選取器） | 使用者主動傳送照片或回報問題並附截圖時 | 讓使用者選擇要傳送或附上的圖片。不是全程讀取相簿。 |

iOS Info.plist 對應字串見 `ios/PTTMobile/Info.plist`（麥克風、使用中／永遠位置、相簿）。系統 Push-to-Talk 另需麥克風與（若啟用鎖屏收聽）Apple Developer 的 Push to Talk 能力。

## Google Play 資料安全表單建議填法

資料是否加密傳輸：是（HTTPS / WSS）。  
使用者是否可要求刪除：是（App 設定與 https://ptt-prototype.onrender.com/delete-account）。

| 資料類型 | 蒐集？ | 分享給其他公司？ | 必填？ | 用途 | 備註 |
|---|---|---|---|---|---|
| 名稱（顯示名稱） | 是 | 否（只在該公司內可見） | 是 | 應用程式功能 | 頻道成員看得到 |
| 使用者 ID / 帳號 | 是 | 否 | 是 | 應用程式功能、帳號管理 | 帳號由公司管理員建立 |
| 密碼 | 是（僅雜湊） | 否 | 是 | 帳號管理 | 伺服器存 scrypt 雜湊，不存明文 |
| 大致／精確位置 | 是（選擇性） | 否 | 否 | 應用程式功能 | 使用者開啟分享才蒐集；只留最新一筆 |
| 麥克風 | 是（即時處理） | 否 | 否 | 應用程式功能 | **不存錄音**。即時轉發給當時在線的收聽者 |
| 照片 | 是（使用者主動傳送） | 否 | 否 | 應用程式功能 | 聊天照片最多保存 7 天 |
| 裝置或其他 ID | 是（問題回報、可選的 iOS PTT token） | 否 | 否 | 應用程式功能、分析／除錯 | 回報日誌已過濾 token／密碼，保留 90 天 |
| 其他使用者內容（文字訊息、字幕、對講 metadata） | 是 | 否 | 否 | 應用程式功能 | 字幕預設不存；對講紀錄不含音訊，保留 90 天 |
| 診斷資料（回報的連線事件） | 是（使用者送出回報時） | 否 | 否 | 應用程式功能、除錯 | 約 200 行，已過濾敏感內容 |

不要勾選：金融資訊、健康、通訊錄、簡訊、已安裝應用程式、廣告 ID、網頁瀏覽紀錄。  
不要宣稱「不與任何第三方分享」時忘記基礎設施（託管於 Render）；表單的「分享」通常指販售或為其他開發者的目的提供。請依當時 Play 定義勾選「服務提供者」如適用。

可能需要列出的「與此 App 連結的資料」或「用於追蹤的資料」（本 App **不用於跨 App 追蹤或廣告**，請選不追蹤）：

**完整介紹**  
Geelo（中文名：吉洛）是給公司與現場團隊使用的即時對講 App。按住按鈕即可對頻道或指定同事說話，也可以傳送文字與照片、呼叫調度台，或在緊急時發出警報。

語音只做即時轉發，伺服器不保存任何錄音；錯過的對話無法事後重聽。照片最多保存 7 天。即時字幕預設只顯示、不存檔（公司管理員可改為只存文字）。你也可以選擇分享目前位置（只保留最新一筆，不建立軌跡）。

帳號由公司管理員建立，登入時需輸入公司代碼。若要刪除帳號，請到 App 設定或開啟：
